# Runnable upstream-inspired gallery

The [gallery](../lmcode/examples/gallery/README.md) contains 32 independently
executable `.lms` examples, each with assertions and online provenance. The
[manifest](../lmcode/examples/gallery/manifest.json) owns the inventory and
expected observations; `lmcode/tests/gallery.py` rejects missing/unlisted examples
and runs all of them through ordinary LMScript preflight and real execution.
`lmcode/examples/run-gallery.lms` is the user-facing LMScript entry point.

## Added bindings

- `english_analyzer`, `whitespace_analyzer`, `Analyzer.tokens(field, text)`.
  Tokens are immutable snapshots with `term`, `position`, `start`, `end`.
  Java/Lucene offsets count UTF-16 code units, not UTF-8 bytes. Token processing
  uses reset/increment/end/close correctly; the analyzer remains reusable.
- `Document.vector_text` enables term vectors with positions and offsets.
  `DirectoryReader.term_vectors(docId, field)` returns unique terms in Lucene
  term order. Each VectorTerm is a collection of occurrence tokens; `len()` is
  its frequency. Missing vectors return an empty collection. Doc IDs belong to
  a reader snapshot; they are not stable application identifiers.
- `Document.sort_number` / `sort_keyword` add single-valued doc values.
  `IndexSearcher.sorted_search(query, field, SortType.LONG|STRING, reverse, limit)`
  collects exact totals and populates real scores before returning the usual hits.
  Fields used by the gallery have a sort value on every document. Missing numeric
  values follow Lucene's default zero behavior; missing string values follow its
  default null ordering. String sorting is term-byte order, not locale collation.
- `IndexSearcher.search_after(query, hit, limit)` uses a score cursor, rejects
  another searcher and field-sorted cursors. Caller must keep the query and
  similarity unchanged across pages. Total is the query's full matching count,
  not the number of documents remaining after the cursor.
- `facet_config`, `Document.facet`, `FacetConfig.build`, `drill_down`,
  `IndexSearcher.facets`. These are real sorted-set doc-values facets. Call
  `build(document)` before indexing and use the same dimension settings at query
  time. `multi_valued` also enables accurate dimension-level document totals.
  FacetCounts represents the requested top labels; `count(label)` returns zero
  for labels outside that returned set. Use a sufficient top limit when checking
  a specific label. Missing matches yield empty counts; missing facet fields or
  unknown dimensions remain Lucene host errors. Hierarchical taxonomy facets and
  DrillSideways remain unbound.
- `Document.vector(field, FloatList)` and both `knn_query` overloads use real
  KnnFloatVectorField/KnnFloatVectorQuery with Euclidean similarity. Components
  are checked before narrowing to float32; empty/non-finite vectors are refused.
  Lucene validates dimensions and its own dimension limits. The filtered overload
  passes its Query into KNN retrieval rather than filtering already chosen hits.
  KNN hit totals describe the selected candidate set, not every vector in the index.
  Examples use explicit 2D vectors and no model service.

## Output and lifecycle

Existing `result.searches` remains. `result.details` carries emitted token streams,
facet counts, and `report(label, text)` explanations. Existing `print` still uses
stderr; every example prints one JSON envelope through its outer LMScript wrapper.
Token/vector/facet snapshots are host-owned values. Existing resource teardown
and separate callback registries still apply. New Lucene operations are refused
from inside SAM callbacks, just like previous operations.

Schema changes invalidate previously compiled bytecode; rebuild/recompile all
`.lms` files after updating the host. The committed DSL schema comes directly
from host registrations and is verified against both compiler and registry.

## Maintenance

Run `./lmcode/test.sh`: original integration groups, new binding failure controls,
and all gallery examples. The single gallery runner is also executable with
`lmscript --no-preflight lmcode/examples/run-gallery.lms`. Use the same root working
directory as the original examples. Generated bytecode and the only persistent
fixture index live beneath ignored `lmcode/build/gallery`; the latter uses
idempotent path updates. Do not run concurrent gallery processes sharing outputs.

Source references describe inspiration and intentional differences, not support
for every upstream feature. Examples are deterministic and self-contained after
build; tests never download data or read the user's documents/manual pages.
